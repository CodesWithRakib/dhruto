# Communication Platform — Phase 5 Authorization Matrix

Rule (unchanged from Phase 2): **access = ACTIVE participant row AND live eligibility** (facts loaded from PostgreSQL on every request/socket check), or a scoped staff `ChatPermission` with a mandatory reason and an audit row. Phase 5 adds: the participant row is kept consistent with eligibility by workflow reconciliation, staff joining an existing thread through get-or-create goes through the audited intervention path, and customer identity uses exact phone equality.

## 1. Parcel thread (`PARCEL_DELIVERY`)

| Actor                                           | Open / create (get-or-create)                                                                                                                                                                                                       | Read / send                                                               | After change                                                                                                                                                       |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Customer                                        | Only if `users.phone` **exactly equals** `parcels.recipient_phone` (same rule as parcel details) and the account is ACTIVE                                                                                                          | Same                                                                      | Phone edited → ineligible immediately; row `REMOVED` on next reconcile                                                                                             |
| Merchant                                        | Only for parcels of their own merchant                                                                                                                                                                                              | Same                                                                      | —                                                                                                                                                                  |
| Rider                                           | Only while `parcels.current_rider_id` = their rider                                                                                                                                                                                 | Same                                                                      | Reassigned away → 404 at once (live); row `REMOVED` + socket revoked when `parcel.assigned.v1` is processed; reassigned back → re-admitted (workflow removal only) |
| Hub manager                                     | Only while actively assigned to the parcel's current hub                                                                                                                                                                            | Same                                                                      | Parcel leaves hub / assignment ends → 404 at once; row reconciled on next event                                                                                    |
| Admin                                           | **New thread:** may create (audited `CONVERSATION_CREATED`). **Existing thread, not a member:** `reason` required → `ADMIN_INTERVENTION` audit + visible "staff joined" system message; without reason → 422 `CHAT_REASON_REQUIRED` | As participant only after joining; otherwise staff read paths with reason | —                                                                                                                                                                  |
| Other merchant / rider / hub manager / customer | 422 `CHAT_SCOPE_INVALID` ("not found or not accessible", no enumeration)                                                                                                                                                            | 404                                                                       | —                                                                                                                                                                  |

## 2. Merchant desk (`MERCHANT_DESK`)

| Actor                          | Access                                                                                                                 |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Merchant                       | Own desk only; `merchantId` is derived server-side, another merchant's id → 422                                        |
| Admin                          | Create a desk for a merchant (audited). Join an existing desk only with `reason` (intervention audit + system message) |
| Hub manager / rider / customer | Not a participant role for this type                                                                                   |
| Internal notes                 | Staff-only endpoints; never returned on participant routes; merchants cannot read them                                 |

## 3. Workflow (system) actor

| Action                        | Who                                                                                                                                        | Audit                                                                                                   | Event                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Remove ineligible participant | Logistics handler (no user) after a committed parcel event, or get-or-create reconciliation                                                | `PARTICIPANT_REMOVED`, `actor_user_id` NULL, metadata `{workflow, reason: "ineligible", sourceEventId}` | `chat.participant_removed.v1` → realtime `participant:updated` + `membership:revoked` |
| Add current rider             | Logistics handler                                                                                                                          | `PARTICIPANT_ADDED`, actor NULL, metadata `{workflow}`                                                  | `chat.participant_added.v1`                                                           |
| Re-admit                      | Only if the latest removal of that user was a **workflow** removal and the user is eligible again; moderator removals are never overridden | `PARTICIPANT_ADDED` (`outcome: reactivated`)                                                            | `chat.participant_added.v1`                                                           |
| System message                | Logistics handler                                                                                                                          | —                                                                                                       | `chat.message_created.v1`                                                             |

Users whose accounts are not ACTIVE are never reconciled (their access is already denied live; suspension is not treated as a membership change).
