# Communication Platform — Phase 7 Security Review

## 1. Controls

| Threat                                   | Control                                                                                                                                                   | Evidence                                                                                                               |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Blanket admin access                     | No implicit path added; every content read still needs a reason + audit; three most sensitive permissions require an explicit, expiring, revocable grant  | Unit (policy), integration (`me`, queue 403, download 404), E2E (ordinary admin denied)                                |
| Self-granted privileges                  | Grants written only by operator CLI; only ACTIVE ADMIN recipients; permission/reason CHECKs; audited                                                      | Integration (non-admin, wrong permission, short reason rejected; no HTTP grant route); CLI run (rider refused)         |
| Cross-tenant / cross-hub access          | Unchanged participant rules; staff scope via `staffHasPermission`; conversation-scoped denials are 404                                                    | Integration + E2E negative tests                                                                                       |
| Internal-note leakage                    | Separate table; staff-only routes; no outbox events; excluded from search/export/history/detail/socket; reads audited                                     | Integration: REST, search, export, outbox payloads, live participant socket with positive control; E2E customer UI/API |
| Inbox leaking content                    | Metadata only; preview/unread only for ACTIVE participant staff; listing audited without search text                                                      | Integration                                                                                                            |
| Search enumeration / injection           | Exact identifier match only; bound parameters; strict schema (unknown keys 422); bounded `q` (64) and `limit` (50)                                        | Integration (`P7-A` partial → empty, SQL-ish input → empty, unknown key → 422)                                         |
| Unscanned / malicious files served       | Serve only `UPLOADED ∧ CLEAN ∧ present`; existing rows default `PENDING`; INFECTED/FAILED cannot be sent                                                  | Unit (gate), integration (pending 409, infected 409, outage → FAILED, tamper → FAILED), E2E with real clamd            |
| Verdict for a different object version   | Hash computed on the scanned stream must equal verified checksum; DB CHECK binds `scanned_sha256`                                                         | Integration (object replaced → `checksum_mismatch`, release refused)                                                   |
| Scanner unavailability                   | Error verdicts only; retries then FAILED; no scanner ⇒ nothing becomes downloadable                                                                       | Unit (unreachable/timeout/garbage/drop), integration (outage), E2E (paused real clamd)                                 |
| Stale worker overwriting staff decisions | Verdict writes conditional on claim (`scan_attempts`)                                                                                                     | Code review; rescan flow integration                                                                                   |
| Restricted content exfiltration          | Grant + reason; audit before URL issuance; always `attachment`; non-clean served as `application/octet-stream`; URLs never logged/audited                 | Integration (content-type, audit metadata has no URL/signature/key)                                                    |
| Evidence destruction                     | Moderation is soft delete with content retained; retention never deletes rows, honors evidence holds, audits purges                                       | Integration (held object kept, purged row kept + audit)                                                                |
| Audit tampering                          | Append-only trigger (unchanged); no write endpoints for audit                                                                                             | Integration (UPDATE rejected; DELETE route 404)                                                                        |
| Escalation abuse / spam                  | ADMIN + permission; note required; idempotent; one notification to a new assignee only                                                                    | Integration                                                                                                            |
| Sensitive data in logs                   | **Found and fixed:** HTTP access log recorded full URLs incl. staff `reason=` and search `q=`; now redacted. Scan/retention logs carry ids and codes only | Unit (`redact-url.spec.ts`); live log check after fix: 0 raw occurrences                                               |
| Rate limiting                            | Existing per-user `chat-admin` (120/min) and `chat-download` limits on all new routes                                                                     | Code review                                                                                                            |

## 2. Residual risks / not provided

1. **Malware detection quality** depends on ClamAV signatures and freshness; ClamAV is not a complete AV solution (no sandboxing, signature-based). Real-clamd EICAR detection only at file start (verified) — content-type checks prevent most masquerades but malicious-but-valid PDFs may pass a stale signature set.
2. **Release is a single-person decision** (grant + reason + audit). Two-person approval is a product decision.
3. Presigned URLs remain 5-minute bearer URLs once issued (unchanged from Phase 6).
4. **ADMIN still holds every non-grant-required permission** platform-wide (by design of Phases 1–6); every read is reason-gated and audited, not prevented.
5. Hub managers have no admin-center view (their own hub moderation continues in the messenger).
6. Retention of message content, audit logs and reports is not defined.
7. The access-log redaction covers query strings only; request bodies were never logged.
8. Load and abuse testing of the inbox and scan job was not performed.
