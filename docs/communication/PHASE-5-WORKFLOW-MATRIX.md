# Communication Platform — Phase 5 Workflow Matrix

Date: 2026-11-15. Derived from the audited source (not from earlier docs alone). "Event" = an existing transactional-outbox domain event; "—" = the workflow publishes no domain event today.

## 1. Logistics workflows found in the source

| Workflow                              | Source                                                                                         | State change                                                                               | Domain event                                               |
| ------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| Parcel created                        | `ParcelsService.create*`                                                                       | `CREATED`                                                                                  | `parcel.created.v1`                                        |
| Rider assigned (fresh or pickup leg)  | `ParcelsService.assignRider`                                                                   | `current_rider_id`, `ASSIGNED_TO_RIDER`; pre-pickup also sets `current_hub_id` = rider hub | `parcel.assigned.v1` (`reassigned: false`)                 |
| Rider reassigned                      | `ParcelsService.assignRider` (from `ASSIGNED_TO_RIDER` / `DELIVERY_ATTEMPTED` / `RESCHEDULED`) | `current_rider_id` changes; previous `parcel_assignments` row closed                       | `parcel.assigned.v1` (`reassigned: true`)                  |
| Out for delivery                      | `RidersService`                                                                                | `OUT_FOR_DELIVERY`                                                                         | `parcel.out_for_delivery.v1`                               |
| Delivered                             | `RidersService`                                                                                | `DELIVERED`                                                                                | `parcel.delivered.v1`                                      |
| Delivery failed / rescheduled         | `RidersService`                                                                                | `DELIVERY_ATTEMPTED` / `RESCHEDULED`                                                       | `parcel.failed.v1` (reason = `DeliveryFailureReason` enum) |
| Returned to merchant                  | `ParcelsService`                                                                               | `RETURNED_TO_MERCHANT`                                                                     | `parcel.returned.v1`                                       |
| Cancelled (pre-pickup only)           | `ParcelsService.cancelParcel`                                                                  | `CANCELLED`                                                                                | —                                                          |
| Hub receive / bag / manifest transfer | `HubsService` scans, manifests                                                                 | `current_hub_id`, hub statuses                                                             | —                                                          |
| Recipient phone edited                | `ParcelsService.update`                                                                        | `recipient_phone`                                                                          | —                                                          |

## 2. Communication workflows (Phase 5)

| #   | Workflow                      | Conversation                                                                                                                                               | Who opens it                                                       | Entry point (UI)                                           | Participants at creation                                                                                         |
| --- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| W1  | Customer ↔ Rider (delivery)   | `PARCEL_DELIVERY` (one per parcel, get-or-create)                                                                                                          | Customer, rider, merchant, hub manager of the parcel's current hub | Customer dashboard active delivery; rider task details     | Merchant user, current rider, registered customer whose phone **exactly** equals the recipient phone, the opener |
| W2  | Parcel-linked operations      | same `PARCEL_DELIVERY` thread                                                                                                                              | Merchant, hub manager, admin (staff path)                          | Merchant/admin parcel details; hub parcel lookup           | as W1                                                                                                            |
| W3  | Merchant ↔ Admin / Operations | `MERCHANT_DESK` (one per merchant, get-or-create)                                                                                                          | Merchant; admin with a reason when joining an existing desk        | Messenger sidebar "Contact operations" (merchant)          | Merchant user, the opener                                                                                        |
| W4  | Rider ↔ Hub manager           | `PARCEL_DELIVERY` thread of a parcel at the manager's hub (hub manager is eligible through the parcel's current hub) and existing `HUB_OPERATIONS` threads | Rider (assigned), hub manager (assigned to the current hub)        | Rider task details; hub parcel lookup                      | as W1                                                                                                            |
| W5  | Support escalation            | Existing staff intervention (`/chat/admin/conversations/:id/intervene`) and `SUPPORT_TICKET`                                                               | Admin / hub manager with `ChatPermission` + reason                 | Existing endpoints (Admin Communication Center is Phase 7) | —                                                                                                                |

No new conversation type was needed: `PARCEL_DELIVERY`, `MERCHANT_DESK`, `HUB_OPERATIONS` and `SUPPORT_TICKET` already model the workflows.

## 3. Lifecycle event → communication effect

| Domain event                                   | Participant reconciliation (existing parcel thread only)                                                                                                                                                                                     | System message (`eventKey`)                     |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `parcel.assigned.v1` (fresh)                   | Ineligible ACTIVE members → `REMOVED` (workflow); current rider added                                                                                                                                                                        | `parcel.rider_assigned`                         |
| `parcel.assigned.v1` (`reassigned`)            | Previous rider → `REMOVED` (workflow), socket revoked; new rider added                                                                                                                                                                       | `parcel.rider_reassigned`                       |
| `parcel.out_for_delivery.v1`                   | reconcile                                                                                                                                                                                                                                    | `parcel.out_for_delivery`                       |
| `parcel.delivered.v1`                          | reconcile                                                                                                                                                                                                                                    | `parcel.delivered`                              |
| `parcel.failed.v1`                             | reconcile                                                                                                                                                                                                                                    | `parcel.delivery_failed` (`reason` = enum code) |
| `parcel.returned.v1`                           | reconcile                                                                                                                                                                                                                                    | `parcel.returned`                               |
| `parcel.created.v1`                            | — (no thread can exist yet)                                                                                                                                                                                                                  | —                                               |
| Cancellation, hub receive/transfer, phone edit | Not event-driven (no domain event). Live eligibility already denies access immediately; stale rows are reconciled on the next lifecycle event or the next get-or-create of the thread; sockets are evicted by the Phase 3 60 s revalidation. | — (documented gap)                              |

Conversations are **never auto-created** by lifecycle events (no thread per parcel unless someone opens one) and **never auto-closed or deleted**; see `PHASE-5-LIFECYCLE-POLICY.md`.
