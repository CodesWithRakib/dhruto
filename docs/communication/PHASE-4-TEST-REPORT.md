## 3. Not executed

- **Playwright E2E.** The existing E2E harness targets the seeded development stack, which does not have migrations 0010/0011 — and applying them there is prohibited. A fully disposable stack (Postgres + Redis + API with chat migrations + web server) also needs chat conversations created through backend flows that are out of Phase 4 scope (parcel lifecycle / admin). No unexecuted spec was added. Runbook for when an isolated stack exists: start disposable Postgres/Redis, run all migrations, boot the API with `DATABASE_URL`, `REDIS_URL`, `CORS_ORIGIN`, `WS_CORS_ORIGINS`; create a conversation via the Phase 2 API; run the web app with `NEXT_PUBLIC_API_URL`; scenarios — two users exchange messages in two browser contexts, offline send → retry, reconnect gap recovery, read ticks, mobile viewport list ↔ thread navigation.
- **Visual / screen-reader manual QA** and **cross-browser** runs were not performed.
- **Load / soak** testing of many concurrent sockets per browser was not performed.

## 4. Environment notes

- Vitest must run from an uppercase-drive cwd (`C:\…`, e.g. PowerShell). From Git Bash (`/c/…`) React is loaded twice and hook tests fail with a null dispatcher — an environment quirk, not a code defect (same issue noted for API e2e in Phase 3).
- `chat-thunks.test.ts` runs in the node environment because undici's `Request` rejects jsdom's `AbortSignal`; `tests/setup.ts` now guards its `window` stubs accordingly.
