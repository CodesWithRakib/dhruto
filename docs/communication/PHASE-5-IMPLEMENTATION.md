# Communication Platform — Phase 5 Implementation

Date: 2026-11-16 · Scope: logistics workflow integration and parcel-linked messaging on the existing platform (no new messaging system, outbox, gateway or notification engine; no migration).

## 1. Decisions approved during implementation

1. **Staff joining an existing thread needs a reason.** `POST /chat/conversations` for an existing `PARCEL_DELIVERY` / `MERCHANT_DESK` thread by an ADMIN who is not an ACTIVE participant now requires `reason` (else 422 `CHAT_REASON_REQUIRED`), the `CONVERSATION_INTERVENE` permission, and runs the same audited intervention writer as `/chat/admin/conversations/:id/intervene`. Creating a new thread is unchanged. (Closes the Phase 2 "no implicit ADMIN access" gap.)
2. **Customer identity = exact phone equality**, the same rule as the parcel module (`recipient_phone = users.phone`). The Phase 2 `+88` normalization was removed because `users.phone` is unique on its raw value, so two accounts could match one parcel.

## 5. Notifications

Parcel events keep their existing in-app/SMS/email/webhook targets unchanged. Per-message chat notifications were **not** added to the notification centre (see limitations); the global unread badge plus the in-messenger realtime cover incoming messages without leaking content to push/SMS/email.
