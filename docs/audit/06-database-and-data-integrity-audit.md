## 3. Money integrity (dual representation — P1 to unify reads)
- Legacy `decimal(12,2)`: `Parcel.cod/weight?/deliveryFee`, `CashLedger.amount/verified`, `Wallet.*`, `WalletTransaction.*`, `PayoutRequest.amount`.
- Phase4+ `bigint minor`: `FinancialEntry/Settlement/Batch/HandIn/Item/Discrepancy/RecipientAggregate` + `money.ts:18-73` (`toMinor/toMajor HALF_UP`, `BDT_MINOR_UNITS=100`).
- Assessment: double-entry (`FinancialTransaction` immutable + `RESTRICT` entries, balanced journals asserted in `finance-ledger.e2e`) is sound; but mixed units risk rounding drift between wallet (decimal) and ledger (minor). Opening balances backfilled idempotently (`0005`, `ensureSeedOpeningBalance`). Reversal via compensating entry (never delete) — correct. `cancelSettlementBatch` orphan must be routed or removed. Payout state machine + idempotency UQ correct. Zero-verify blocked — confirm business rule.

## 4. Constraints / isolation / concurrency
- **Tenant isolation:** `merchantId` present on money/parcel/notification/webhook/risk tables; services scope by JWT (verified for parcels/finance/notifications/webhooks). `RECIPIENT` aggregates keyed `(phoneHash,merchant)` — correct per-merchant risk. Analytics e2e asserts cross-tenant denial (good).
- **Cascades (minimal, correct):** only notifications/webhooks/hub-assignments/manifest-items/hand-in-items CASCADE; `FinancialEntry→Transaction RESTRICT` (prevents ledger orphaning). No soft-delete → deletes are hard (verify no delete routes expose `remove` on ledger/parcel).
- **Concurrency:** `(key,scope) UQ` + claim-in-tx for idempotency; `(parcel,attempt) UQ`, `parcel/ledger UQ`, `(sub,event) UQ`, `dedupe UQ` prevent doubles; `SKIP LOCKED` outbox poller; `finance-ledger.e2e` covers double-verify serialize + completion concurrency (good). `RateLimitGuard inFlight` memory + `CacheService` fallback are the weak points (multi-instance drift — see `13`).
- **Indexes:** parcel list covered incl. Phase8; hub/bag/manifest/exception/scan/history/ledger/finance/notification/webhook/intel/alert/report all indexed for their query patterns. Missing-index risk: low statically; needs `EXPLAIN` on analytics range queries (task in `15`).
- **Migrations (10):** 0000 baseline → 0001 reconcile (renames + backfills) → 0002 hub ops (manifest_items replaces `bag_ids` jsonb, partial UQs) → 0003 rider OTP hash (replaces plaintext) → 0004 finance ledger → 0005 opening balances (data, idempotent, down no-op) → 0006 notifications/integrations → 0007 intelligence (HMAC-only) → 0008 analytics → 0009 parcel list index. `down` drops all (0000) — never run in prod (documented).
- **Seeds:** deterministic upserts (`seeder.service.ts:90-594`); 5 hubs, role users (`dhruto123`), merchants/riders/wallets/parcels+histories/intel/finance/notifications/inactive webhooks; `ensureImported + ensureDefaults` for geo/models. Safe for dev/CI (`db:setup`); never prod.
