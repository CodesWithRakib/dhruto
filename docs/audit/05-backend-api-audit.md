## 2. Cross-cutting findings
- **Unused/duplicated:** `useGetParcelHistoryQuery` (no page), `useTestSms` (no page), `cancelSettlementBatch` (no route), `getDefaultMerchant` fallback (avoid), analytics legacy vs v2 overlap.
- **Contract alignment:** backend DTOs `implements ContractType` structurally matched; Zod at event/outbox boundary, `class-validator` at HTTP. Divergences: bag-add raw body, pricing `codAmount`, webhook `events`, analytics dual query shapes, finance zero-verify, SMS phone — all P1/P2 tasks in `15`.
- **Idempotency:** required/optional correctly on create/money/OTP-complete/hand-in/report; same-key+diff-payload → 409 (tested). Verify `AssignRider` + `dispatch/receive` idempotency (no key observed — task).
- **Pagination/sorting:** `ParcelListQueryDto` supports offset + cursor fields simultaneously (see `10` for consolidation); analytics `limit1-200`; rider history fixed `page1/limit100` (frontend); webhook deliveries paged; notification prefs bounded.
- Detail catalogs: `api/` (one file per module + `queues-events.md` + `contracts.md`).
